# BB Weekly Dashboard Refactor

ไฟล์นี้ถูกแยกจาก `bb.html` เพื่อให้แก้ไขเร็วขึ้นและลดความเสี่ยงในการแก้โค้ดผิดจุด

## โครงสร้าง

- `index.html` — Layout หลัก, Sidebar, Header, CDN Tailwind/Lucide/Chart.js
- `css/style.css` — CSS เดิมทั้งหมด
- `js/helpers.js` — Utility functions และ calculation helpers
- `js/charts.js` — Chart defaults, progress plugin, chart กลางของ Overview
- `js/data.js` — ดึงข้อมูล Google Sheets, parse CSV, mock data fallback
- `js/app.js` — State, navigation, event handlers, controller
- `js/pages/*.js` — Render function รายหน้า

## วิธีเปิดใช้งาน

เปิด `index.html` ผ่าน local server เช่น VS Code Live Server หรือ deploy ขึ้น Cloudflare Pages/GitHub Pages ได้เลย

> แนะนำ: อย่าเปิดผ่าน `file://` หาก browser บล็อกการ fetch Google Sheets CSV ให้ใช้ Live Server แทน

## Monthly Summary

เลือก **สรุปรายเดือน (Monthly)** ในเมนู Main Dashboard แล้วเลือกเดือน/ปีจากแถบหัวด้านบน
ชื่อเดือน ช่วงวันที่ ตัวเลือกเดือน และปุ่มเต็มจอรวมอยู่ในแถบหัวเดียว เพื่อเพิ่มพื้นที่แสดงข้อมูล
หัวข้อทั้ง 5 ฝ่ายระบุเดือนที่เลือก และ Marketing มีการ์ดรวมทั้งหมดก่อนรายละเอียด GFS / MHL / CAR
เมื่อเข้าเต็มจอ เมนูด้านซ้ายจะซ่อนอัตโนมัติ และคืนสถานะเดิมเมื่อออกจากเต็มจอ
มีสรุปยอดขายเทียบเป้าและรายละเอียดครบ 5 ฝ่ายในหน้าเดียว ได้แก่ Marketing,
Sales Admin, ฝ่ายขายฟิล์มอาคารและ Projects, ฝ่ายขายฟิล์มรถยนต์ และทีมช่างอาคาร
พร้อมปุ่มเลื่อนไปแต่ละฝ่าย ตารางสัปดาห์ที่นำมารวม และปุ่มเต็มจอเดิม

Monthly เป็นหน้าแยก ไม่เปลี่ยนหน้าเริ่มต้น Overview, `selectedId`, ตัวกรอง Weekly,
สูตรเดิม หรือรูปแบบ Google Sheets การเปลี่ยนเดือนและกลับ Weekly จะคง Week ที่เลือกไว้
ปุ่มรีเฟรชยังใช้ `loadData()` เดิม (ซึ่งเลือก Week ล่าสุดตามพฤติกรรมเดิม)
Monthly จะจำเดือนที่เลือกตราบที่เดือนนั้นยังอยู่ในข้อมูล และไม่สร้างการ fetch เพิ่มเมื่อเปลี่ยนเดือน

ไฟล์ที่เพิ่ม:

- `js/monthly-data.js` — รวมข้อมูลแบบอ่านอย่างเดียว คืนชุดข้อมูลใหม่ ไม่แก้ Weekly
- `js/pages/monthly.js` — หน้า Monthly และสถานะเลือกเดือนแยกกัน
- `css/monthly.css` — รูปแบบเฉพาะ `.monthly-*` ไม่แก้ CSS เดิม
- `tests/monthly*.cjs` — ทดสอบสูตร การสลับหน้า และการเทียบข้อมูลต้นทาง

จุดเชื่อมกับของเดิมมีเฉพาะลิงก์/ไฟล์ประกอบใน `index.html` และทางแยก Monthly
ใน `js/app.js` ก่อนคำนวณ Weekly กรณี Monthly ขัดข้องยังกลับไป Weekly ได้
ไม่มี dependency ใหม่ และไม่มีการเผยแพร่หรือแก้ชีตจากฟีเจอร์นี้

### กติกาข้อมูล

- รวมเฉพาะ Week ที่ตัวอ่านเดิมส่งมา ไม่รวมคอลัมน์ Monthly ซ้ำ และไม่ได้เพิ่ม Week 0 ที่ตัวอ่านเดิมข้าม
- สัปดาห์คร่อมเดือนนับทั้งสัปดาห์เข้าเดือนวันสิ้นสุด ไม่ใช่การแบ่งตามวันปฏิทิน
- รองรับชื่อเดือนไทย ปี ค.ศ./พ.ศ. และช่วงข้ามปี; ไม่ระบุปีใช้ปีของแหล่ง BB-2026
- เป้ารายเดือนรวมทุกสัปดาห์ในเดือน แม้เป็นสัปดาห์อนาคต ยอดผลงานรวมค่าตาม Weekly
- ยอดขายรวมใช้ `getTotalSalesActual/Target` เดิม ส่วนยอดแยกธุรกิจคงค่าต้นทาง ไม่บังคับให้เท่ากัน
- ROAS = ยอดขายรวม / ค่าโฆษณารวม; % คำนวณจากผลรวม ไม่บวก/เฉลี่ยเปอร์เซ็นต์รายสัปดาห์
- ไม่รวมยอดสะสม YTD/จำนวนทีมข้ามสัปดาห์ และยังไม่แสดงเป้าเทคนิคที่มี mapping ทับกับยอดสะสมในตัวอ่านเดิม
- ตัวเลือกเดือนหนึ่งจุดควบคุมข้อมูลของทั้ง 5 ฝ่าย และยอดรายละเอียดของแต่ละฝ่ายไม่ถูกบวกทับกันเป็นยอดขายบริษัท
- ยอดฝ่ายขายอาคารรายบุคคลรวมเฉพาะ 5 Sales Rep และ 3 Projects ที่แสดงในหน้า Weekly เดิม โดยคำนวณอัตราจากผลรวมเดือน
- ฝ่ายขายรถยนต์ยึดยอดรวมของส่วน CAR และคำนวณความเสียหายจากมูลค่าปัญหาจริง ไม่ใช้ช่องเปอร์เซ็นต์ที่ mapping ซ้ำ
- ค่าศูนย์ไม่ถือว่าเป็นข้อมูลหายโดยอัตโนมัติ สัปดาห์ที่มีเป้าแต่ค่าผลงานทั้งหมดเป็นศูนย์จะแสดง “รอยืนยัน” โดยไม่ตัดออก
- ไม่สรุป % เทียบเดือนก่อนเมื่อเป็นเดือนเปิด/อนาคต มีสัปดาห์รอยืนยัน หรือมีข้อมูลจากแผน
- ช่วงวันที่อ่านไม่ได้จะแสดงรายการที่ยังไม่รวม แทนการเดาเดือน
- โหมด `row-weekly-plan` มีค่าผลงานที่ตัวอ่านเดิมอนุมานจากเป้า Monthly แสดงคำเตือนและงดอัตราผลงาน โดยไม่เปลี่ยนตัวอ่าน Weekly
- ถ้า Weekly ใช้ข้อมูลจำลองเนื่องจากอ่านชีตไม่ได้ Monthly จะแสดงข้อความให้ลองใหม่ ไม่ใช้ข้อมูลจำลองทำรายงาน
- ข้อมูลเป็นชุดเดียวกับการรีเฟรช Weekly ไม่ได้ยืนยันว่าปิดเดือนหรือกรอกครบแล้ว

กราฟแท่งเปรียบเทียบยอดกับเป้าใช้หน่วยบาท/ฐานศูนย์/ลำดับเดือน มีตารางตัวเลขสำรองและคำเตือนแหล่งข้อมูล
โดยคงตัวแสดงกราฟ Chart.js ของเว็บเดิม ไม่ย้ายไปเครื่องมือหรือระบบเผยแพร่ใหม่

### ค่าใช้จ่ายรวมรายเดือน

แท่งค่าใช้จ่ายสีส้มซ้อนอยู่ในกราฟยอดขายสีฟ้า อ่านชีต `ค่าใช้จ่าย` (gid `152606837`) ในไฟล์ Google Sheets เดียวกัน
ใช้เฉพาะแถว `TOTAL` ตามหัวเดือน ไม่บวกแถวอาคาร/รถยนต์ซ้ำ และไม่ใช้คอลัมน์ยอดรวมทั้งปี
ปีบนกราฟตามตัวเลือก Monthly; เดือนที่เลือกถูกเน้นด้วยสีเข้มและจุด ส่วนตารางร่วมแสดงค่าใช้จ่ายถึงสตางค์
ใช้แกนบาทและฐานศูนย์เดียวกัน: แท่งยอดขายกว้างอยู่ด้านหลัง แท่งค่าใช้จ่ายแคบอยู่ด้านหน้า ไม่ใช่การบวกยอดแบบ stacked
คงเส้นเป้ายอดขายและสถานะถึงเป้าไว้ จับคู่ด้วยปี-เดือน; เดือนที่มีเฉพาะค่าใช้จ่ายยังแสดงโดยยอดขาย/เป้าเป็นช่องว่าง
ตารางเรียงเดือน → เป้าหมาย → ยอดขาย (พื้นเขียว) → ค่าใช้จ่าย (พื้นแดง) → ส่วนต่าง → % เทียบเป้า
ส่วนต่างคำนวณยอดขายลบค่าใช้จ่ายจากค่าต้นทางก่อนปัดเป็นสตางค์;
ถ้าขาดข้อมูลฝั่งใดฝั่งหนึ่งหรือยอดขายมาจากแผนจะแสดง “—” แทนการสมมติเป็นศูนย์
ท้ายตารางมีแถวรวมตามเดือนที่แสดง โดยรวมค่าต้นทางก่อนปัด และคำนวณ % จากยอดขายรวม/เป้ารวม ไม่เฉลี่ย % รายเดือน
ถ้ายังมีเดือนขาดค่าใช้จ่าย ส่วนต่างรวมทุกเดือนจะแสดง “—” และเพิ่มแถวรวมเฉพาะเดือนที่มียอดขายและค่าใช้จ่ายให้เปรียบเทียบช่วงเดียวกัน

- `js/expense-data.js` อ่านข้อมูลแยกจากยอดขายเมื่อเปิดเว็บ/รีเฟรช ไม่ดึงซ้ำเมื่อเปลี่ยนเดือน
- `js/pages/monthly-expenses.js` จับคู่ค่าใช้จ่ายและเตรียมหมายเหตุ/ลิงก์ต้นทางให้กราฟร่วมใน `js/pages/monthly.js`
- แถว TOTAL เป็นศูนย์แต่รายการทุกแถวว่าง จะแสดง “ยังไม่มีข้อมูล”; ศูนย์ที่มีการกรอกจริงยังคงเป็นศูนย์
- ค่าผิดรูปแบบ/โหลดล้มเหลวไม่ถูกแทนด้วยศูนย์ ข้อมูลเก่า หรือข้อมูลจำลอง; ยอดขายเดิมยังใช้งานได้
- ยอดที่สูงกว่าค่าสูงสุดของเดือนก่อนหน้าเกิน 4 เท่า (มีฐานอย่างน้อย 3 เดือน) หรือมีรูปแบบคล้ายยอดสะสม
  จะแสดงหมายเหตุให้ตรวจสอบ โดยไม่แก้ไข/ตัดยอดต้นทางออก ไม่ถือว่าเป็นข้อผิดพลาดที่ยืนยันแล้ว
- เวลา “อ่านล่าสุด” คือเวลาที่เว็บอ่านชีต ไม่ใช่เวลาปิดบัญชีหรือเวลาที่ผู้ใช้แก้ไขชีต

```powershell
node --test tests/expenses.test.cjs tests/monthly.test.cjs tests/monthly-departments.test.cjs tests/monthly-integration.test.cjs
$expenseResponse = Invoke-WebRequest -Uri 'https://docs.google.com/spreadsheets/d/12BRnIWVT227cltrdeukIAOIEJ_qrL3OH0Aw6a7gIDIo/export?format=csv&gid=152606837'

```
